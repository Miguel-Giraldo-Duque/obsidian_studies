
### Como hacerlo?

Para la creación de [[Pruebas de usuabilidad]] como cualquier otro [[Testeo]] debemos definir objetivos , crear metricas y demás pasos , en este caso para un test de ususabilidad debemos

- Definir el objetivo : Que queremos lograr con la prueba?.
- Definir una métrica : Que métrica vamos a usar cualitativo o cuantitativo?.
- Definir un tipo de test : Que test vamos a llevar A/B, entrevista?.
- Definir documentación : Es necesario cuando estamos trabajando con pruebas. como las escritas donde requerimos guardar mucha mas informacion.
- Definir tareas : Que acciones debe hacer mi  usuario en la pagina?.
- Definir participantes: Reclutar los participantes.
- Llevar a cabo la prueba
- Analizar los resultados
- Crear un presentación de los problemas de ususabilidad y posibles recomendaciones para solucionarlos


#### Definición de objetivos 

Cuando estamos creando una prueba de ususabilidad debemos definir objetivos claros bajo los cuales validar , es prioritario no tener mas de 3 objetivos y si se necesitan mas buscar  priorizar lo mas importante

Una prueba de ususabilidad requerirá que hablemos con el equipo técnico o ventas dependiendo de lo que se quiere evaluar si lo que queremos es validar con las personas una nueva funcionalidad  problamente hablaremos mas con el equipo tecnico , si queremos rediseñar para un mejor engament con ventas etc.

#### Creación de metricas 


Cuando estamos llevando una [[Pruebas de usuabilidad]] tenemos los dos tipos de prueba cualitativo y cuantitativo y como cualquier buena prueba necesitamos metricas para medir el éxito .


**Metricas cuantivas** : Podemos medir la cantidad, los heatmaps , tiempo, y porcentajes en la respuestas frente a pruebas como A/B o  encuestas


**Metricas cualitativas** :  Lo podemos medir por :
- Éxito en la tarea : el usuario logra terminar la tarea que le asignamos ?
- Tiempo para realizar la tarea : Cuanto tiempo le toma a el usuario completar la tarea?
- Errores: Cuales fueron lo errores que usuario experimento durante la tarea ? 
- Satisfacción subjetiva del usuario : Que tan difícil en la percepción del usuario le fue completar una tarea? 



### Definición de tareas 

Cuando estamos creando tareas debemos asegurarnos de definir que tipo de 
tareas vamos a hacer que es usuario lleve a cabo

- Tareas cerradas : Tareas muy especificas donde limitamos el rango para evaluar partes especificas y evaluamos el éxito de forma exitosa o no ejemplo compra una pc si el usuario no lo logra consideramos como experiencia de aprendizaje.

- Tareas búsqueda del tesoro : Le indicamos al usuario un objetivo aunque no por completo le entreguemos pistas para lograrlo

-  Tareas búsqueda del tesoro inverso:  Empezamos entregándole al usuario que 

- Tareas abiertas : Buscamos que a través de una tarea abierta que no implique necesariamente un mismo orden de acciones y pueden haber diferentes caminos para completarla , queremos evaluar de estos caminos toma y que dificultades presenta. 

 - Tareas especificas:  Le otorgamos al usuario unas tareas que por si mismas si que implican un camino especifico como : Compra un pantalón 
 
-  Auto Tareas : Buscamos que usuario construya sus propias tareas en base a sus expectativas con la pagina, le preguntamos que esperarías ver esta sección de la pagina ? R// Creo que esperaría una sección con los planes de pago y sobre reseñas  (Esa seria la tarea que le asignamos)

- Tareas de exploración : Le pedimos al usuario que por si mismo explore la pagina e interactúe con esta , no es lo ideal dado que no es como normalmente las personas ingresamos a interactuar a un pagina , como personas venimos con una necesidad o un esenario por detras.

### Reclutamiento participantes

Con 5 participantes encontramos 85% de problemas con nuestra aplicación. 

Es una parte difícil del proceso dado los pasos que debemos realizar para tener un buen participante debemos entender  quien es el publico a evaluar debemos buscar que este [[User persona]] evitar cerrarlo mucho para obtener una buena cantidad de participantes,   la forma de obtener un participante se puede dividir en

-  Reclutamiento pasillo :  Podemos ir y reclutar a personas en persona para que participen en nuestra interfaz .

- En nuestra web : Podemos comunicarnos en nuestra propia web un anuncio para una prueba de ususabilidad  y podemos enviar correos a los usuarios que están en nuestra aplicación 

- En campañas de marketing o anuncios : Podemos poner un anuncio para que personas se inscriban y participen en la prueba de ususabilidad

**Incentivos**
La idea con este mensaje es clave entender hacerle entender al usuario cuando se va llevar a cabo la prueba  y que va tener un incentivo para participar este puede ser : dinero , un valor que a la persona le interese por ejemplo si es una tienda vegana descuentos durante todo diciembre, si es una tech una prueba gratuita para probar  la nueva funcionalidad
